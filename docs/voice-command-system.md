# نظام الأوامر الصوتية الذكي (AI Voice Command System)

مساعد صوتي عربي يفهم **النية** ويستخرج **البيانات** وينفّذ **سلاسل عمليات** داخل
النظام — لا مجرد تحويل صوت إلى نص. مبني على مبادئ **Clean Architecture** و
**Domain-Driven Design** و**SOLID**، ومفصول بالكامل عن واجهة المستخدم وعن مزوّد
الذكاء الاصطناعي.

> هذا توثيق **المرحلة الأولى (الأساس + شريحة عمودية عاملة)**. خارطة الطريق لبقية
> القدرات في آخر المستند.

---

## 1. المبدأ المعماري

الفكرة الجوهرية: **فصل «الفهم» عن «التنفيذ» عن «مزوّد الذكاء»**.

```
        (المتصفح)                         (الخادم — Fastify)
┌───────────────────────┐     نص      ┌──────────────────────────────────────────┐
│  Speech-To-Text        │ ─────────► │  NLU Provider (Port)                       │
│  useSpeechRecognition  │            │   └─ RuleBasedNluProvider (Adapter)        │
│  (Web Speech API)      │            │   └─ [مستقبلاً] LlmNluProvider              │
└───────────────────────┘            └──────────────────┬───────────────────────┘
        ▲      │ ClientAction                            │ NluResult (intent+entities)
        │      ▼                                         ▼
┌───────────────────────┐            ┌──────────────────────────────────────────┐
│  VoiceAssistant.vue    │ ◄────────  │  Context → Workflow → Permission →         │
│  voice.store (Pinia)   │  TurnResp  │  Confirmation → Executor(Transaction)      │
└───────────────────────┘            │           → Audit / Session Persistence     │
                                     └──────────────────────────────────────────┘
```

كل صندوق وحدة مستقلة قابلة للاختبار والاستبدال. الواجهة لا تملك أي **سياسة**
(ماذا يُسمح، ماذا يحتاج تأكيداً) — تعرض فقط ما يقرّره الخادم.

## 2. خط المعالجة (Pipeline) — دورة واحدة

| # | المرحلة | الوحدة | المسؤولية |
|---|---------|--------|-----------|
| 1 | Speech-To-Text | `useSpeechRecognition.ts` | صوت → نص (في المتصفح) |
| 2 | Intent Recognition | `RuleBasedNluProvider` | نص → نية (لا مطابقة جُمَل) |
| 3 | Entity Extraction | `entity-extractor.ts` | مساحة/واجهة/نزال/اسم/نوع… |
| 4 | Context Awareness | `ContextManager` | «باسمه»، «نفس المشروع»، تجميع الخانات |
| 5 | Workflow (Slot-fill) | `WorkflowEngine` | خانات ناقصة → سؤال توضيحي / بناء الخطة |
| 6 | Permission | `PermissionEngine` | يحترم صلاحيات RBAC لكل خطوة |
| 7 | Confirmation | `ConfirmationEngine` | لا تنفيذ لعملية تُغيّر البيانات بلا تأكيد |
| 8 | Transaction Execution | `Executor` | كل الخطوات في معاملة واحدة + Rollback |
| 9 | Audit | `VoiceRepository` + `AuditService` | سجل كامل لكل أمر |
| 10 | Session | `VoiceSession` (DB) | ذاكرة المحادثة عبر الأدوار |

المنسّق `VoiceService` يربط هذه الوحدات ولا يملك أي منطق مجال أو تعرّف بنفسه.

## 3. بروتوكول «الدور» (Turn Protocol)

المحادثة آلة حالات صغيرة يقودها رد مُميَّز (discriminated union) من الخادم:

| الرد | المعنى | تصرّف الواجهة |
|------|--------|---------------|
| `clarify` | نية مفهومة لكن خانة ناقصة | يطرح السؤال ويعيد الاستماع |
| `confirm` | خطة جاهزة تنتظر نعم/لا | يعرض الملخص + أزرار تأكيد/إلغاء |
| `executed` | نُفِّذ (أو إجراء واجهة) | يطبّق `clientActions` (تنقّل/توست) |
| `rejected` | مرفوض (صلاحية/غموض/غير مدعوم) | يعرض السبب |

نقطتا الدخول:
- `POST /api/v1/voice/interpret` — `{ sessionId?, transcript, locale }`
- `POST /api/v1/voice/decision` — `{ sessionId, planId, decision }`

كلاهما محميّ بصلاحية `voice.use`، ثم **كل عملية فعلية تُفحَص ثانيةً** داخل
`PermissionEngine` (دفاع بالعمق: VIEWER يقدر يفتح المساعد ويتنقّل، لكن
`create_project` يُرفض ما لم يملك `projects.create`).

> العقود (DTOs) كلها في `@contractor-plus/shared/voice` ليتشاركها الطرفان.

## 4. كيف تُضيف أمراً جديداً (Open/Closed)

دون لمس جوهر النظام:

1. أضِف اسم النية في `packages/shared/src/voice/intents.ts`.
2. علّم المفردات في `backend/.../nlu/arabic-lexicon.ts` (بيانات، لا منطق).
3. نفّذ `IntentHandler` جديداً (خاناته المطلوبة + بناء الخطة).
4. سجّله في `backend/.../engine/intents/index.ts`.

مثال الواجهة الوحيدة التي تكتبها:

```ts
export class CreateProjectHandler implements IntentHandler {
  readonly intent = VoiceIntent.CREATE_PROJECT;
  readonly requiredSlots = [
    { name: 'area', read: (b) => b.area, question: 'ما هي مساحة المشروع؟' },
  ];
  plan(input): Plan { /* خطوات + ملخص تأكيد + صلاحيات مطلوبة */ }
}
```

لا حاجة لتعديل `WorkflowEngine` أو `Executor` أو `PermissionEngine` أو
`VoiceService` إطلاقاً.

## 5. طبقة الفهم الطبيعي + LLM (Provider-Agnostic)

طبقة **فوق** المحرك المستقر (لا تغيّر شيئاً تحتها). مكوّناتها:

- **`NaturalCommandInterpreter`**: الواجهة العليا. تُنتج **نفس الأشكال** التي يستهلكها
  المحرك أصلاً (`NluResult` للأمر المفرد، و`IntentInvocation[]` للسلسلة) — لذا
  WorkflowManager/Handlers/Permission/Confirmation/Executor تعمل **دون تغيير**
  سواء جاء الفهم من القواعد أو من الـ LLM.
- **`NluProviderRouter`**: يختار المزوّد. يبقى **RuleBased** هو الأساس والافتراضي،
  ويُصعّد للـ LLM فقط عند: نية UNKNOWN، ثقة منخفضة (لهجة/كلام غير مرتب)، أو جملة طويلة
  قد تكون مركّبة بلا روابط صريحة. الأوامر البسيطة الواضحة لا تلمس الـ LLM إطلاقاً.
- **`LlmNluProvider`** + **`LlmClient`** (محوّلات Anthropic/OpenAI عبر `fetch`
  بمهلة صارمة). يحوّل الكلام إلى **JSON منظم فقط** (intents/entities/missingFields/
  clarificationQuestion/confidence). **لا ينفّذ، لا يصل لقاعدة البيانات، لا يستدعي
  Services، لا يرى بيانات عملاء أو أسعاراً داخلية.** المُرسَل: المفردات الثابتة + نص
  المستخدم + ثلاث قيم منطقية (هل يوجد مشروع/عقد/عميل سابق) لحلّ «هذا/نفس». كل مخرجات
  الـ LLM تُتحقَّق وتُصفّى (نوايا غير معروفة تُسقَط) فيبقى المحرك هو المرجع.

**Fallback كامل**: عند تعطيل الـ LLM، أو غياب المفتاح، أو المهلة، أو الفشل، أو مخرجات
غير صالحة → يُستخدم RuleBased والمستخدم لا يشعر بشيء.

**الإعدادات** (متغيّرات بيئة، **معطّل افتراضياً**، والمفتاح في البيئة فقط لا في القاعدة):
`VOICE_LLM_ENABLED`, `VOICE_LLM_PROVIDER` (anthropic|openai), `VOICE_LLM_MODEL`,
`VOICE_LLM_API_KEY`, `VOICE_LLM_TIMEOUT_MS`, `VOICE_LLM_MAX_TOKENS`,
`VOICE_LLM_MIN_CONFIDENCE`.

**التدقيق**: كل دور يسجّل المزوّد الذي أجاب (`rule-based-ar` / `llm:anthropic` /
`rule-based:llm-fallback`) + الثقة + المستخدم + الوقت. **لا يُسجَّل** المفتاح ولا
الاستجابة الخام.

> الـ STT أيضاً خلف منفذ في `useSpeechRecognition` ويمكن تبديله بـ Whisper/سحابي
> دون لمس بقية النظام.

## 6. قاعدة البيانات

نموذجان جديدان (Prisma / PostgreSQL) — هجرة
`prisma/migrations/20260630120000_voice_command_system`:

- **`VoiceSession`** — خيط محادثة واحد + ذاكرة سياق (`context` JSON: آخر عميل/
  مشروع، الخانات المتراكمة، الخطة المعلّقة).
- **`VoiceCommandLog`** — سجل غير قابل للتعديل لكل نطق: النص الأصلي + المُطبَّع +
  النية + الثقة + الكيانات + الخطة + الحالة + النتيجة/الخطأ + المزوّد
  (المرحلة الرابعة عشرة: Audit Log).

> الأمر المعلّق **لا يُخزَّن كدالة** — نخزّن (intent + entities + transcript)
> ونعيد بناء الخطة عند التأكيد، فتبقى الخطة المنفّذة دائماً محقّقة للصلاحيات
> لحظة التنفيذ.

## 7. الأمان والمعاملات

- **الصلاحيات**: `voice.use` على المسار، ثم فحص لكل خطوة عبر `AccessService`
  (نفس دلالات RBAC في الخادم؛ OWNER يتجاوز).

- **الذرّية**: كل خطوات الخطة في `prisma.$transaction` واحدة — فشل خطوة = تراجع
  الكل (المرحلة العاشرة)، وتُكتب تدوينة التدقيق ضمن نفس المعاملة.

## 10. المراحل المنفّذة

**المرحلة 1 (الأساس):** المنظومة الكاملة (NLU/سياق/Workflow/تأكيد/صلاحيات/معاملة/
تدقيق/جلسة) + `create_project` (خادمية) و`navigate` (واجهية)، مع توضيح متعدّد
الأدوار (clarify→answer عبر `fillFromAnswer`).

**المرحلة 2A (المالية):** `create_contract` ذرّي (عميل + قالب + عقد + تقدير المواد)
مع **Template Matching** فعلي (يعيد استخدام مُستخرِج الكيانات على أسماء القوالب) و
**Material Intelligence** عبر دالة تقدير نقية واحدة (`contracts.estimate.ts`)
يتشاركها `generateEstimate` (يكتب) و`previewEstimate` (يعرض السعر المقترح في
التأكيد). سعر المتر والطوابق خانتان إلزاميتان (لا افتراضات مالية).

**المرحلة 2B (الأوامر المركّبة + Saga):**
- **Multi-Intent Segmenter** (`compound-segmenter.ts`): يقسم على الروابط
  (،/ثم/بعدها) ويرتّب حسب أولوية النوايا.
- **Context Chaining / Shared Context**: نتائج كل نية (projectId/contractId/…)
  تُحقن في `SessionContext` فتستعملها النية التالية أو أمر لاحق دون إعادة ذكرها.
- **WorkflowManager (Saga)**: كل نية في معاملة مستقلة (لأن السير يتوقّف عبر أدوار
  HTTP للتوضيح/التأكيد فلا يمكن إبقاء معاملة واحدة مفتوحة)؛ تأكيد موحّد واحد لكل
  السلسلة؛ **تعويض (Compensation) عكسي** عند فشل نية لاحقة أو الإلغاء؛ واستئناف
  بعد التوضيح دون إعادة البدء.
- `add_cost` / `add_payment` / `generate_materials` (سياقية، بتعويض).

**المرحلة 2C (`link_project_to_contract`):** يربط مشروعاً مستقلاً بعقد فيقبل
الدفعات. يحلّ المشروع/العقد من السياق («اربط هذا المشروع بالعقد») أو من إشارة
صريحة («... بالعقد رقم V-2026-0004»). فشل الحلّ → توضيح؛ التعارض (مربوط مسبقاً /
عقد ملغى / عقد له مشروع) → 409. `add_payment` لمشروع بلا عقد لم يعد يفشل بصمت —
يسأل: «هذا المشروع غير مرتبط بعقد...». الربط ذرّي ومُدقّق، وله تعويض (فكّ الربط)
للـ Saga. أصلحت هنا علتين كامنتين: تسرّب كيانات الأدوار السابقة إلى الأوامر الجديدة،
ومطابقة عبارات قصيرة («لا») كسلسلة فرعية داخل كلمات أطول.

**اختبارات:** 34 وحدة + 14 تكامل (HTTP حقيقي + DB) تغطّي: أمر واحد، أمرين، أربع
نوايا، فشل في المنتصف + Rollback تعويضي، استئناف بعد التوضيح/التأكيد، وكل سيناريوهات
الربط (آخر↔آخر، محدّد↔محدّد، تعارض، بوابة الدفعة قبل/بعد الربط).

**المرحلة 3 (الفهم الطبيعي + LLM):** طبقة `NaturalCommandInterpreter` +
`NluProviderRouter` + `LlmNluProvider` (Anthropic/OpenAI) **فوق** المحرك دون
تغييره — راجع §5. مفعّلة بمتغيّرات البيئة، **معطّلة افتراضياً**، وRuleBased يبقى
الأساس والـ Fallback الدائم.

## 11. التشغيل والإعدادات النهائية (Operations)

### 11.1 تفعيل الـ LLM عبر متغيّرات البيئة

الطبقة الذكية **معطّلة افتراضياً**. لتفعيلها أضِف هذه المتغيّرات لبيئة الخلفية
(في التطوير: `backend/.env`). المفتاح يُقرأ من البيئة **فقط** — لا يُحفظ في القاعدة
ولا يُرسَل للواجهة ولا يُسجَّل.

| المتغيّر | الافتراضي | الوصف |
|---------|-----------|------|
| `VOICE_LLM_ENABLED` | `false` | المفتاح الرئيسي. `false` = RuleBased وحده |
| `VOICE_LLM_PROVIDER` | `anthropic` | `anthropic` أو `openai` |
| `VOICE_LLM_MODEL` | `claude-haiku-4-5` (anthropic) / `gpt-4o-mini` (openai) | معرّف النموذج |
| `VOICE_LLM_API_KEY` | — | **البيئة فقط**؛ بدونه يبقى النظام على RuleBased |
| `VOICE_LLM_TIMEOUT_MS` | `6000` | مهلة صارمة؛ تجاوزها ⇒ Fallback |
| `VOICE_LLM_MAX_TOKENS` | `700` | حدّ مخرجات النموذج |
| `VOICE_LLM_MIN_CONFIDENCE` | `0.6` | تحت هذه الثقة يُصعّد الـ Router للـ LLM |

```bash
# مثال تفعيل (backend/.env) — معطّل افتراضياً، فلا حاجة لشيء لتشغيله على RuleBased
VOICE_LLM_ENABLED=true
VOICE_LLM_PROVIDER=anthropic
VOICE_LLM_MODEL=claude-haiku-4-5
VOICE_LLM_API_KEY=...            # في البيئة فقط — لا في القاعدة، لا في الكود
```

> **معطّل افتراضياً:** عند غياب `VOICE_LLM_ENABLED=true` أو غياب المفتاح، يبني
> `createLlmClient` قيمة `null`، فيعمل النظام **بالكامل** على `RuleBasedNluProvider`
> كما لو أن طبقة الـ LLM غير موجودة.

### 11.2 التنفيذ يبقى عبر المحرك المستقر فقط

الـ LLM **لا ينفّذ شيئاً** — يُرجع JSON منظماً فقط. كل تنفيذ يمرّ حصراً عبر:

```
WorkflowEngine  →  PermissionEngine  →  ConfirmationEngine  →  Executor
   (بناء الخطة)      (صلاحية كل خطوة)      (تأكيد ما يُغيّر)       (معاملة + Saga)
```

سواء جاء الفهم من القواعد أو من الـ LLM، المخرجات بنفس الشكل (`NluResult` /
`IntentInvocation[]`) فلا يتغيّر أي شيء تحت هذه الطبقات. الـ LLM لا يصل لقاعدة
البيانات ولا يستدعي Services ولا يكتب ولا يغيّر بيانات.

### 11.3 RuleBased هو الـ Fallback الدائم

`RuleBasedNluProvider` هو الأساس والـ Offline/Fallback في كل الحالات التالية —
**دون أن يشعر المستخدم بشيء**:

- الـ LLM معطّل، أو لا يوجد مفتاح.
- انتهت المهلة (`VOICE_LLM_TIMEOUT_MS`).
- فشل المزوّد (خطأ HTTP/شبكة).
- مخرجات LLM غير صالحة أو بلا نية معروفة.

## 12. أمثلة أوامر صوتية (لهجة عراقية / عربية طبيعية)

### 12.1 تعمل على RuleBased (Offline، بلا LLM)

| الأمر | النتيجة |
|------|---------|
| «سويلي مشروع بيت مية متر» | إنشاء مشروع بيت، المساحة 100 |
| «سوي مشروع عمارة مساحة 200 طابقين» | مشروع عمارة، 200م²، طابقان |
| «سوي عقد باسم أحمد مساحة 100 واجهة 5 نزال 20 طابقين بسعر 250 ألف» | عقد كامل + مطابقة قالب + تقدير مواد |
| «اشتريت حديد بقيمة 5 ملايين» | تكلفة 5,000,000 (تصنيف: مواد) |
| «أضف تكلفة 500 ألف» | تكلفة 500,000 على المشروع الحالي |
| «أضف دفعة مليون» | دفعة 1,000,000 (يسأل المشروع إن لزم) |
| «اربط هذا المشروع بالعقد» | ربط آخر مشروع بآخر عقد |
| «اربط مشروع بيت 100 بالعقد رقم V-2026-0004» | ربط محدّد بالإشارة |
| «افتح المشاريع» / «اعرض العقود» | تنقّل |
| «سوي مشروع بيت مساحة 100، وأضف تكلفة 500 ألف» | سلسلة (أمران، بتأكيد موحّد) |
| «سوي مشروع بيت» ← «مساحته 200» | توضيح ثم استئناف |

### 12.2 حيث يساعد الـ LLM (لهجة/كلام غير مرتب)

هذه يلتقطها الـ Router ويُصعّدها للـ LLM (إن فُعِّل)، وإلا تُرفض بلطف:

| الأمر | لماذا يحتاج LLM |
|------|----------------|
| «ولدلي مشروع داخل عقد لأحمد» | مرادفات غير معجمية («ولدلي»، «داخل») + نيّتان |

## 13. Smoke Test Checklist (يدوي)

شغّل الخلفية (`pnpm --filter backend dev`) والواجهة، سجّل الدخول بمستخدم له
`voice.use`، ثم عبر زر المساعد (أو الإدخال النصّي البديل):

- [ ] **تنقّل**: «افتح المشاريع» → ينتقل لصفحة المشاريع فوراً (بلا تأكيد).
- [ ] **إنشاء بسيط**: «سوي مشروع بيت مساحة 100» → يعرض تأكيداً → «تأكيد» → يُنشأ المشروع.
- [ ] **توضيح**: «سوي مشروع بيت» → يسأل «ما مساحة المشروع؟» → «200» → تأكيد → تنفيذ.
- [ ] **عقد + مواد**: «سوي عقد باسم أحمد مساحة 100 واجهة 5 نزال 20 طابقين بسعر 250 ألف»
      → تأكيد يعرض القالب والسعر المقترح → تنفيذ → يُملأ بند المواد.
- [ ] **سلسلة**: «سوي مشروع بيت مساحة 100، وأضف تكلفة 500 ألف» → تأكيد موحّد → تنفيذ متسلسل.
- [ ] **ربط ثم دفعة**: «أضف دفعة مليون لهذا المشروع» (قبل الربط) → يطلب الربط؛
      «اربط هذا المشروع بالعقد» → تأكيد؛ ثم «أضف دفعة مليون» → ينجح.
- [ ] **صلاحية**: بمستخدم `viewer` جرّب «سوي مشروع» → يُرفض (permission_denied).
- [ ] **إلغاء**: أي عملية بانتظار التأكيد → «إلغاء» → لا تُنفَّذ.
- [ ] **Fallback**: فعّل `VOICE_LLM_ENABLED=true` بمفتاح خاطئ → الأوامر البسيطة
      تبقى تعمل (RuleBased) دون أي خطأ ظاهر للمستخدم.

> اختبارات آلية مكافئة: `pnpm --filter backend test` (34) و`test:integration` (14).

## 14. الأمان (تأكيد نهائي)

- **لا مفاتيح في الكود** — مؤكَّد بـ grep على `src/modules/voice` (لا أي `sk-...`).
- **المفتاح في البيئة فقط** (`VOICE_LLM_API_KEY`) — لا في القاعدة، لا يُرسَل للواجهة،
  ولا يُسجَّل في `VoiceCommandLog` (يُسجَّل اسم المزوّد فقط: `rule-based-ar` /
  `llm:anthropic` / `rule-based:llm-fallback`).
- **لا يُسجَّل الرد الخام للـ LLM** — يُحلَّل ويُصفَّى إلى `EntityBag` مُتحقَّق منه فقط.
- **أقل قدر من البيانات يُرسَل للـ LLM**: المفردات الثابتة + نص المستخدم + ثلاث قيم
  منطقية (هل يوجد مشروع/عقد/عميل سابق). **لا أسماء عملاء، لا أسعار داخلية، لا قاعدة
  بيانات.**
